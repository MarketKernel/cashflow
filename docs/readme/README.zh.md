**Cashflow** 无需记录每一笔开支就能跟踪个人财务。你只需设置一次账户、债务和定期收支。然后不时**对账**：
输入实际余额。应用会算出有多少钱未被记录，预测未来几个月的状况，告诉你钱还能用多久，以及什么时候
能买到想要的东西。

整个应用是一个可离线运行的独立 HTML 文件：无需账号、无需云端、不发出任何网络请求。数据是一个
SQLite 数据库（SQLite 编译为 WebAssembly，内嵌在文件中），由浏览器保存在本设备上。同一个页面也是
一个可安装的 PWA，能在自己的窗口中运行。

![Cashflow：按货币分类的账户、个人资金、报告与预测](../cashflow.png)

## 使用方法

1. 打开 <https://cash.marketkernel.com> 上的在线版本，或从发布页下载 `cashflow-<version>.html`
   （或自行构建：`./build.sh`），然后在浏览器中打开——直接从磁盘打开也可以。
2. 选择本位货币：所有总额都以它显示。在**设置**中添加你持有的其他货币及其汇率——需手动输入，应用
   从不联网。
3. 在**账户**中添加你的账户（银行卡、现金、存款、交易所账户）和债务（信用卡、贷款、借款），并填写
   各自当前的余额。
4. 点击**对账**（或按 <kbd>R</kbd>）。每个字段都已填好预期余额；只需修改不同之处并保存。预测从这里
   开始。
5. 在**定期**中添加工资、房租、订阅、信用卡的月供——可以是每天、每周、每月或每年。在**单次**中添加
   定期项目未覆盖的内容：一笔购物、一笔奖金、一次计划中的假期。
6. 每隔一两周再次对账。报告会告诉你有多少钱未被记录（如果它反复出现，还会提供计划应对的选项）、
   钱还能用多久，**目标**页面中的各项目标也会告诉你何时能买到它们。

### 在手机上

标签页会移到屏幕底部的栏中，表单则以底部弹出面板的形式打开；键盘不会遮住正在输入的字段。从
<https://cash.marketkernel.com> 安装在线版本：在 Android 上，通过 Chrome 的 ⋮ 菜单 → 安装应用；
在 iOS 上，通过分享 → 添加到主屏幕。设备之间不会同步：要迁移数据，请在一台设备上导出，再在另一台
设备上导入（设置 → 数据）。

## 工作原理

### 对账

一次对账是某一时刻所有账户和债务真实余额的快照。表单会为每个账户显示记录所预期的数值：上次记录的
余额，加上此后属于该账户的每一笔操作。你只需修改不同之处。快照会保留当时的余额、名称、手续费和
汇率，并且永远不会重新计算：重命名账户、归档账户、编辑某项操作或更改本位货币，都不会改变过去的对账
记录。只有最后一次对账可以被删除——用于撤销一次误操作的对账。

### 未记录资金从何而来

对于每种货币，应用会把预期值——上次记录的余额、此后新建账户的初始余额，以及该区间内每一笔定期和
单次操作——加总起来，并与你输入的实际值比较。差额就是未记录资金：负值表示有支出未被记录，正值表示
有收入未被记录。它按每种货币分别统计，而不是按本位货币的总额统计，因此两次对账之间汇率的变动不会
被当成一笔支出。新建账户会带上它的初始余额，因此创建账户不会算作未记录的收入；归档一个仍有余额的
账户时，应用会询问这笔钱去了哪里（转到了另一账户，还是被花掉了），这样同样不会产生未记录的资金。

### 预测与"资金可维持到"

预测从最后一次对账开始，加上此后的每一笔操作——这就是"当前预计"。从这里起，预测逐日推进到预测范围
（默认五年）：只计入定期操作和已计划的单次操作，不计入其他任何内容。"资金可维持到"指的是账户资金
首次降为零的时刻；如果个人资金（账户资金减去债务）更早跌破零，该日期会作为第二条信息显示。如果在
预测范围内两者都不会发生，报告会说明资金可以维持更久——如果资金在增长，还会说明每月增长多少。目标
按其顺序购买，最靠前的先买：某个目标的日期，是预测首次达到其门槛值加上排在它前面的目标价格之和的
时刻，且不早于排在它前面的目标的日期。

未记录资金不会被单独纳入计划：丢失的钱包或一次性的维修，不应让此后的每个月看起来都更拮据。报告
转而显示它的平均速度——截至最后一次对账的 90 天内各次对账的未记录资金，除以相应的天数——并且，
对于支出，会提供将其添加为一笔不关联账户的每日定期支出的选项。一旦添加，预测就会像对待其他任何
操作一样计入它，此后的对账将只显示超出这部分之外的未记录金额。未记录的收入不计入预测。

### 手续费，以及为什么债务的手续费会让它变大

账户的手续费，是把其资金折算为本位货币时所损失的比例：手续费为 1 % 的账户里的 1 000 USD，折合
1 000 × 41.5 × 0.99 = 41 085 UAH。债务的手续费则相反——**这是一项默认的设计决定**：用另一种货币
偿还债务，或通过中间人偿还，代价会高于其票面金额，因此手续费为 2 % 的 200 USD 债务，折算为
200 × 41.5 × 1.02 = 8 466 UAH 的欠款。账户之外的资金以及目标的价格，则按原始汇率换算。

### 为什么删除一项操作不会改变过去

一项定期操作拥有多个版本。编辑它会关闭当前生效的版本，并从此刻起新建一个版本；删除它则只是关闭
当前版本。自上次对账以来的时间段，仍按当时生效的版本计算，因此下一次对账不会出现意外，已完成的
对账也永远不会改变。日期早于最后一次对账的单次操作处于一个已关闭的区间：可以作为备注保留，但不会
改变任何计算。

贷款利息不会被建模：请将它作为一项定期支出添加，而还款本身则作为向该债务的一笔转账。

## 功能

- 账户和债务按货币分组、可折叠，显示该货币的总额及折合本位货币的总额；个人资金以大号字体显示。
- 支持任意 2–10 位字母数字的货币代码（USD、EUR、USDT、BTC），各自拥有自己的小数位数；金额以最小
  货币单位的整数存储，因此不存在舍入误差累积。
- 金额可以用逗号或句点输入，千位之间可以用空格或撇号分隔，并支持简单的算术运算：`1200+350-50*2`。
- 定期操作支持每天（可指定时间）、每周、每月（指定某一天，或最后一天）或每年，从某一时刻起生效，
  直到某个日期为止；在天数较少的月份，31 日会被视为该月的最后一天，平年的 2 月 29 日则按 2 月 28
  日处理。时间按当地时间计算，因此每天 09:00 的操作在夏令时切换前后仍保持 09:00。
- 单次操作通过按钮（或按 N 键）打开的表单添加：光标默认停在金额字段，按 Enter 保存，
  并记住上次使用的账户。列表默认显示下一次对账将计入的操作；筛选器可显示两次历史对账之间的区间、全部操作，
  或指定起止日期，并显示所显示操作的合计。
- 支持在不同货币的账户之间转账，按入账金额记录；转入债务的转账会用于偿还该债务。
- 预测图表可选一周、一个月、3 个月、6 个月或一年：显示个人资金、账户资金、零线和各项目标；带有
  显示具体数值的十字准线，也可以表格形式查看相同的数据。
- 目标可以设置为"留有余地"购买（个人资金至少达到价格加上一定余量）或"按比例"购买（价格不超过个人
  资金的某个比例），按优先级排列成一个列表：把某个目标拖到更靠前，就能更早买到它。点击"已购买"会
  记录这笔支出。
- 打开一次过去的对账记录，会按当时的状态显示账户页面，包括预期值、实际值，以及该区间内的记录。
- 支持以 JSON 或 SQLite 文件本身导出和导入，后者还可以用密码加密，用作保存在别处的副本；在
  Chrome 和 Edge 中，每次更改后都会自动把副本写入你选择的文件。
- 一个浏览器中可以有多个数据库——比如一个用于家庭，一个用于某项业务——每个都有自己的账户、目标
  和PIN码。多于一个时，应用会先打开它们的列表，当前打开的那个的名称会显示在顶部栏中（点击可
  返回列表）。导入的文件会替换当前打开的数据库，或作为它旁边的一个新数据库。
- 设置中的"删除此数据库…"：会先经过一次提示，提供导出，并在设置了 PIN码 时要求输入；只有一个
  数据库时，它会被一个新的空数据库取代。
- 创建数据库时会要求设置一个四位 PIN码：在输入它之前页面不会显示任何内容，而且每输错一次，下次
  重试前的等待时间就会翻倍，从一秒一直到一小时。
- 浅色与深色主题，17 种语言，阿拉伯语和乌尔都语支持从右到左排版，并提供手机布局。

## 安全与隐私

- 没有任何数据离开页面。`src/app/template.html` 中的内容安全策略（Content Security Policy）设置了
  `default-src 'none'` 和 `connect-src 'none'`；为 SQLite 允许了 WebAssembly（`'wasm-unsafe-eval'`），
  为导出下载允许了 `blob:`。构建过程会在发现任何外部 `src` 或 `href` 时中止，CI 还会再次检查。
- 数据保存在此浏览器的 IndexedDB 中：每个数据库对应一条记录，保存着它的 SQLite 字节内容，每次
  更改后都会整体重写，因此保存操作不会出现只完成一半的情况；另有一条记录保存着数据库列表。
  `localStorage` 仅保存语言、主题、当前打开的标签页、折叠的分组、图表的区间，以及 PIN码 输错后的
  等待时间；`sessionStorage` 保存该标签页打开的是哪个数据库。
- 读取数据库或导入的文件时会检查每一个字段：损坏的值会被替换为默认值，而不会导致应用停止运行。
- 首次保存之后，应用会请求浏览器保留其存储空间（`navigator.storage.persist()`），这样磁盘空间
  不足时不会导致数据被清除。
- PIN码能防止接触到未锁定电脑的人，但无法防止复制浏览器文件的人：数据本身并未加密。只保存其
  哈希值（加盐的 PBKDF2），哈希值作为数据库设置的一部分存放，因此导出文件也会带有它，无论导入到
  哪里都会要求输入同一个 PIN码。忘记的 PIN码无法找回：点击"忘记PIN码？"需先输入数据库的名称才会删除数据库并新建一个
  空的数据库，这样乱按按钮的孩子就不会把它清除。
- 若要保存一份放在云端文件夹或U盘中的副本，"导出加密文件…"会用至少 8 个字符的密码加密 SQLite
  文件：使用 PBKDF2-SHA-256 派生密钥（60 万次迭代，随机盐值）的 AES-256-GCM。没有密码任何人都无法
  打开该文件——包括 Cashflow 在内——忘记的密码也无法找回。导入该文件时会要求输入密码。浏览器中的
  数据保持原样，仍受 PIN码 保护。

## 翻译

英文原文保留在代码中：`t('accounts', 'Reconcile')`、`tn('time', '{count} day ago', '{count} days
ago', n)`，以及模板中的 `data-i18n="context"` / `data-i18n-attr="context"`。第一个参数是上下文——
即该字符串所属的界面部分，因此同一个英文单词在两处可以被翻译成不同的内容。一个字典文件
`src/locales/<code>.json` 将"上下文 → 英文文本"映射到对应的译文：

```json
{
  "accounts": { "Reconcile": "Сверить" },
  "time": { "{count} days ago": { "one": "{count} день назад", "few": "{count} дня назад", "many": "{count} дней назад", "other": "{count} дня назад" } }
}
```

字典中缺失的字符串会显示为英文。带数字的文本会为该语言的每个复数类别各提供一种形式（基于
`Intl.PluralRules`），并以英文的复数形式作为键。`npm run i18n` 会按语言列出尚未翻译的字符串，以及
不再使用的字符串；`npm test` 会检查每条译文是否保留了英文的占位符，并包含所有复数形式。"Cashflow"
这个名字永远不会被翻译。

本 README 同样会被翻译：每种语言对应一个 `docs/readme/README.<code>.md` 文件，每个文件顶部都有
语言列表。这里的改动也应当同步到各个译文中。

## 构建

```sh
./build.sh            # 如有需要会先安装依赖，然后构建出 build/cashflow.html
npm install
npm run build         # -> build/cashflow.html 和 build/pages/
npm run watch         # 监听 src/ 下的更改并自动重新构建
npm run typecheck     # tsc --noEmit
npm test              # 核心逻辑测试：money、valuation、schedules、reconciliation、forecast、goals、state、SQLite、字典
npm run test:browser  # 在无头 Chrome 中测试构建出的页面和 PWA
npm run i18n          # 列出各字典缺失或不再需要的字符串
npm run check         # 依次运行 typecheck、test、build 和 test:browser
npm run shots -- shots/after  # 构建后，把每个标签页的截图保存到 shots/after
node tools/icons.mjs  # 根据 assets/icon.svg 生成 PWA 的 PNG 图标
```

`build.mjs` 使用 esbuild 将 `src/app/main.ts` 打包成一个 IIFE——SQLite 的 WebAssembly 通过 esbuild
的二进制加载器以字节形式嵌入——然后连同样式和图标（一个 data URI）一起，替换进
`src/app/template.html` 中。结果就是大约 1.4 MB 的 `build/cashflow.html`：其中大部分是 SQLite，
其次是 16 个语言字典。

同一次运行还会写入 `build/pages/`：即该页面作为可安装 PWA 的版本——带有 manifest 链接和
`<meta name="service-worker">`（告诉页面注册其 service worker）的 `index.html`、
`manifest.webmanifest`、图标，以及负责缓存页面以便离线打开的 `sw.js`。

`tests/app.mjs` 通过 DevTools 协议（`tools/chrome.mjs`，无任何依赖）在无头 Chrome 中驱动构建出的
页面：首次启动、任务示例中的账户及其总额、相隔一周的两次对账（未记录 −1 500）、删除一项操作而不
改变历史、一次过去的对账、目标、导出 → 清空 → 导入、PWA 的离线运行及其更新、手机布局，以及从磁盘
打开的页面仍保留其数据。测试不会等待时间流逝：在页面自身的脚本之前插入的一段脚本会替换
`Date.now()`，时区设为 Europe/Kyiv，因此包含夏令时切换的一周也会被测试到。

## 版本与发布

版本号只写在一个地方：`package.json`。构建过程会把它写入页面（设置页面底部）以及 PWA 的缓存名称
中。打了 `v<version>` 标签的提交构建出的版本会原样显示版本号；其他任何提交都会附加其提交号，例如
`0.1.0+1a2b3c4`，这样来自 `main` 分支的页面就不会被误认为正式发布版本。

```sh
npm version minor           # 0.1.0 -> 0.2.0：更新 package.json、package-lock.json，创建一次提交和标签 v0.2.0
git push --follow-tags      # 该标签会触发 .github/workflows/release.yml
```

如果标签与 `package.json` 中的版本号不一致，发布工作流会中止；否则会附加上 `cashflow-<tag>.html`
和 `SHA256SUMS.txt`。

## GitHub Pages

`.github/workflows/pages.yml` 会在每次推送到 `main` 时进行构建和测试，并将 `build/pages/` 部署到
GitHub Pages（设置 → Pages → Source：GitHub Actions）。它部署在 <https://cash.marketkernel.com>：
该域名在 设置 → Pages → Custom domain 中设置，并开启了 Enforce HTTPS——service worker 需要
HTTPS。通过工作流部署无需 `CNAME` 文件。`build/pages/` 中的每一个路径都是相对路径，因此同一份
构建既能运行在某个域名的根目录下，也能运行在某个项目站点的 `/<repo>/` 前缀下。

在线版本的数据归属于它的网址；从磁盘打开的副本则拥有自己独立的数据。旧地址
`marketkernel.github.io/cashflow/` 现在会重定向到该域名，但它的数据仍留在原处：曾经用过它的人应
先在那里导出数据（从那里安装的应用会继续离线运行），再在新地址导入。

每次部署都会更改 `sw.js` 中的缓存名称，因此浏览器会自行获取新的 worker——可能在有网络连接时启动
应用、应用保持打开期间每隔几个小时，或者在设置 → **检查更新**被点击时触发。新的 worker 会把自己的
版本下载到专属的缓存中并等待；当前运行的页面仍会继续提供旧页面，即使离线也是如此。此时设置标签页
上会出现一个圆点，提示"版本……已就绪"：点击**更新**会保存正在等待的内容，让新的 worker 接管，并
重新加载页面，页面会提示一次已完成更新。如果不点按钮，新版本会在应用的所有窗口都关闭后自行启用。
已下载的文件会保持其版本不变；若要确定磁盘上某个版本，可从某次发布中获取 `cashflow-<tag>.html`，
并与 `SHA256SUMS.txt` 比对。

## 局限性

- 设备之间不会同步：数据只保存在输入它的那个浏览器中。要迁移数据，需要在一台设备上导出，再在
  另一台设备上导入。
- 汇率需要手动输入：应用从不会为此联网获取。
- 从磁盘打开的页面，数据保存在该浏览器用于本地文件的存储空间中。Chrome 和 Edge 会保留这些数据
  （浏览器测试会检查这一点）；Firefox 和 Safari 通常也会，但某些配置和隐私窗口不会——此时页面顶部
  会给出提示，并只在内存中运行：请导出数据，或改用已安装的应用。
- 贷款利息不会被建模；需要你自行添加为一项定期支出。
- 目标按顺序一个接一个地购买：列表中排在后面的便宜目标，即使现在就能买到，也要等排在它前面的
  目标先买。

**Cashflow** は、支出をいちいち記録しなくても個人の家計を把握できるアプリです。口座、負債、定期的な
収支を一度だけ設定します。そして、ときどき**照合**を行います：実際の残高を入力するのです。アプリは、
どれだけのお金が記録されていなかったかを割り出し、この先の数か月を予測し、資金がいつまで持つか、
欲しいものがいつ買えるかを教えてくれます。

アプリ全体がオフラインで動く一つの独立した HTML ファイルです：アカウント登録もクラウドもネットワーク
通信も不要です。データは SQLite データベース（WebAssembly にコンパイルされた SQLite がファイル内に
組み込まれています）で、ブラウザがこの端末上に保持します。同じページは PWA でもあり、インストール
して専用のウィンドウで実行できます。

![Cashflow：通貨ごとの口座、純資金、レポートと予測](../cashflow.png)

## 使い方

1. <https://cash.marketkernel.com> のオンライン版を開く、またはリリースから
   `cashflow-<version>.html` をダウンロードする（または `./build.sh` で自分でビルドする）。そして
   ブラウザで開く——ディスクから直接開いても問題ありません。
2. 基準通貨を選ぶ：すべての合計はこの通貨で表示されます。**設定**で、保有している他の通貨をレート
   とともに追加する——レートは手入力です。アプリは決してオンラインに接続しません。
3. **口座**で、口座（カード、現金、預金、取引所）と負債（クレジットカード、ローン、借入金）を、
   それぞれ現在の残高とともに追加する。
4. **照合する**を押す（または <kbd>R</kbd> キー）。各項目にはすでに見込み残高が入っています。違う
   部分だけ修正して保存する。予測はここから始まります。
5. **定期**で、給料、家賃、サブスク、カードの月々の支払いなどを追加する——毎日、毎週、毎月、毎年の
   いずれかで設定できます。**単発**では、定期的な項目でカバーされないもの、たとえば買い物やボーナス、
   予定している旅行などを追加する。
6. 1、2週間ごとに再び照合する。レポートが、どれだけのお金が未記録だったか（繰り返すなら、それを
   見込む方法も示します）、資金がいつまで持つかを教えてくれます。そして**目標**ページの各目標が、
   いつ買えるようになるかを教えてくれます。

### 携帯電話での利用

タブは画面下部のバーに移動し、フォームは画面下からシートとして開きます。キーボードは入力中の項目
を覆いません。<https://cash.marketkernel.com> のオンライン版をインストールするには：Android では
Chrome の ⋮ メニュー → アプリをインストール、iOS では共有 → ホーム画面に追加、を使います。端末間の
同期はありません：データを移すには、一方の端末でエクスポートし、もう一方でインポートしてください
（設定 → データ）。

## 仕組み

### 照合

照合とは、ある瞬間における全口座・全負債の実際の残高のスナップショットです。フォームには、各口座に
ついて記録上の見込み値——前回確認した残高に、それ以降にその口座に関わるすべての操作を加えたもの——が
表示されます。違う部分だけを修正します。スナップショットはその時点の残高、名前、手数料、レートを
保持し、決して再計算されません：口座名の変更、アーカイブ、操作の編集、基準通貨の変更を行っても、
過去の照合はそのまま変わりません。削除できるのは最後の照合だけです——誤って行った照合を取り消す
ためです。

### 未記録の資金はどこから来るのか

通貨ごとに、アプリは見込み値——前回確認した残高、その後に作成された口座の初期残高、そしてその期間
内のすべての定期操作と単発操作——を合計し、入力された実際の値と比較します。その差が未記録の資金
です：マイナスは記録されなかった支出を、プラスは記録されなかった収入を意味します。これは基準通貨
での合計ではなく、通貨ごとに集計されるため、2回の照合の間に為替レートが変動しても支出とは見なされ
ません。新しい口座にはその初期残高が伴うため、口座を作成しても未記録の収入にはなりません。残高が
残っている口座をアーカイブする際には、そのお金がどこへ行ったか（別の口座か、使われたか）を尋ねるので、
ここでも未記録にはなりません。

### 予測と「資金は……まで持つ」

予測は最後の照合から始まり、それ以降のすべての操作を加えます——これが「現在の見込み」です。そこから
予測期間（デフォルトで5年）まで、1日ずつ進めていきます：定期操作と予定されている単発操作だけで、
それ以外は含みません。「資金は……まで持つ」は、口座残高が初めてゼロに達する時点を指します。純資金
（口座残高から負債を引いたもの）がそれより早くマイナスになる場合は、その日付が2番目に示されます。
どちらも予測期間内に起きない場合、レポートは資金がもっと長く持つこと——あるいは資金が増えているなら、
月々どれだけ増えるか——を伝えます。目標は優先順位の順に、上から購入されます：ある目標の日付は、
その上にある目標の日付より早くなることはなく、予測がその閾値に上の目標の価格を加えた額へ達する
最初の時点です。

未記録の資金はそれだけでは予測に見込まれません：なくした財布や一度きりの修理費のために、この先の
月がすべて苦しくなるようなことがあってはならないからです。代わりにレポートはその平均ペース——直近
の照合までの90日間の各照合の未記録の資金を、その日数で割ったもの——を示し、支出については、口座を
持たない毎日の定期支出として追加することを提案します。追加すると、予測はほかの操作と同じようにそれ
を見込むようになり、以降の照合はそれを超えて未記録になった分だけを示します。未記録の収入は見込まれ
ません。

### 手数料と、負債の手数料がそれを大きくする理由

口座の手数料とは、その資金を基準通貨に換算する際に失われる割合のことです：手数料1%の口座にある
1 000 USDは、1 000 × 41.5 × 0.99 = 41 085 UAHの価値になります。負債の手数料はこれと逆方向に働き
ます——**これは既定の設計上の判断です**：負債を別の通貨で、あるいは仲介者を介して返済すると、額面
以上の費用がかかるため、手数料2%の200 USDの負債は、200 × 41.5 × 1.02 = 8 466 UAHの負債として計算
されます。口座の外にあるお金と目標の価格は、そのままのレートで換算されます。

### 操作を削除しても過去が変わらない理由

定期操作にはバージョンがあります。編集すると、現在有効なバージョンを締めて、今から新しいバージョン
を開きます。削除すると、現在のバージョンを締めるだけです。最後の照合からの期間は、当時有効だった
バージョンで引き続き計算されるため、次の照合で予期しない結果にはならず、すでに行われた照合が変わる
こともありません。最後の照合より前の日付を持つ単発操作は締められた期間にあり、メモとして残すことは
できますが、計算には何も影響しません。

ローンの利息はモデル化されていません：定期的な支出として追加し、返済そのものはその負債への振替
として追加してください。

## 機能

- 口座と負債を通貨ごとにグループ化し、折りたたみ可能。その通貨での合計と基準通貨換算の合計を表示
  し、純資金は大きな文字で表示されます。
- 2〜10文字の英数字であれば任意の通貨コード（USD、EUR、USDT、BTC）を使え、それぞれ独自の小数桁数を
  持てます。金額は最小単位の整数として扱われるため、丸め誤差が蓄積することはありません。
- 金額はカンマまたはピリオドで入力でき、桁区切りにはスペースやアポストロフィを使えます。さらに
  `1200+350-50*2` のような簡単な四則演算もできます。
- 定期操作は毎日（時刻指定あり）、毎週、毎月（特定の日、または最終日）、毎年のいずれかで設定でき、
  ある時点から特定の日付まで有効にできます。日数の少ない月では31日はその月の最終日として扱われ、
  平年の2月29日は2月28日として扱われます。時刻はローカル時間なので、毎日09:00の操作は夏時間の
  切り替えをまたいでも09:00のままです。
- 単発操作はボタン（または<kbd>N</kbd>）の先のフォームで入力します。カーソルは金額欄に置かれ、
  Enterで保存、前回使った口座が記憶されます。一覧は初期状態で次回の照合が対象とする範囲を表示し、
  フィルターで過去2回の照合の間の期間、すべて、または日付の範囲（から～まで）を指定でき、表示され
  ている操作の合計も示されます。
- 異なる通貨の口座間での振替に対応し、入金額を基準に記録されます。負債への振替はその負債の返済に
  なります。
- 予測グラフは1週間、1か月、3か月、6か月、1年の期間で表示でき、純資金、口座残高、ゼロのライン、
  各目標を示します。数値を表示するクロスヘアがあり、同じ数値を表としても見られます。
- 目標は「余裕を残す」（純資金が価格に一定額を足した額以上）か「割合で」（価格が純資金の一定割合
  以下）のいずれかで購入判定でき、優先順位順のリストに並びます。ドラッグして上に動かすと早く
  購入できます。「購入済み」にするとその支出が記録されます。
- 過去の照合を開くと、当時の口座タブの状態——見込み値、実際の値、その期間に記録された内容——が表示
  されます。
- JSON、またはSQLiteファイルそのもの（後者は別の場所に保管するコピー用にパスワードで暗号化する
  こともできます）としてエクスポート・インポートできます。ChromeとEdgeでは、変更のたびに選択した
  ファイルへ自動的にコピーが書き込まれます。
- 同じブラウザ内に複数のデータベースを持てます——たとえば家族用と事業用など——それぞれに専用の
  口座、目標、暗証番号があります。複数ある場合、アプリは一覧画面から起動し、開いているデータベース
  の名前は上部のバーに表示されます（クリックすると一覧に戻ります）。ファイルをインポートすると、
  開いているデータベースを置き換えるか、その横に新しいデータベースとして追加されます。
- 「このデータベースを削除…」は設定にあり、警告でエクスポートを提案し、暗証番号があればそれを
  尋ねます。唯一のデータベースの場合は、新しい空のデータベースに置き換わります。
- データベースを作成するときに尋ねられる4桁の暗証番号：入力するまでページには何も表示されず、
  間違えるたびに次の試行までの待ち時間が1秒から1時間まで倍々に増えていきます。
- ライトテーマとダークテーマ、17の言語、アラビア語とウルドゥー語の右から左へのレイアウト、携帯電話
  向けレイアウトに対応しています。

## キーボードショートカット

| キー | 動作 |
| --- | --- |
| <kbd>R</kbd> | 照合する |
| <kbd>N</kbd> | 開いているタブで口座・定期操作・単発操作・目標を新規作成する |

## セキュリティとプライバシー

- 何もページの外へ送信されません。`src/app/template.html` のコンテンツセキュリティポリシーは
  `default-src 'none'` と `connect-src 'none'` を設定しています。SQLiteのために WebAssembly
  （`'wasm-unsafe-eval'`）、エクスポートのダウンロードのために `blob:` のみが許可されています。
  外部の `src` や `href` が見つかるとビルドは停止し、CIでも再度チェックされます。
- データはこのブラウザのIndexedDBに保存されます：データベースごとにそのSQLiteバイト列を保持する
  レコードが1件あり、変更のたびに丸ごと書き込まれるため保存が中途半端な状態になることはなく、
  さらにデータベースの一覧を保持するレコードが1件あります。`localStorage` には言語、テーマ、
  開いているタブ、折りたたまれたグループ、グラフの期間、間違った暗証番号を入力した後の待ち時間
  だけが保存されます。`sessionStorage` には、このタブがどのデータベースを開いたかが保存されます。
- データベースやインポートしたファイルを読み込む際は、すべての項目をチェックします。壊れた値は
  アプリを停止させる代わりに既定値に置き換えられます。
- 最初の保存の後、アプリはブラウザにストレージの保持を依頼します（`navigator.storage.persist()`）。
  これにより、ディスク容量が不足してもデータが失われることはありません。
- 暗証番号は、ロックしていないパソコンの前に来た人を防ぐためのもので、ブラウザのファイルを
  コピーする相手を防ぐものではありません：データ自体は暗号化されていません。保存されるのはその
  ハッシュだけで、データベース内の設定の一部として保存されるため、エクスポートにも含まれ、インポー
  ト先でも同じ暗証番号が求められます。暗証番号を忘れると復元できません：「暗証番号をお忘れですか？」
  でデータベースを削除し、新しい空のものを作成します——ただし、データベースの名前を入力した場合の
  みで、子どもがボタンを押しても消えないようになっています。
- クラウドフォルダやUSBメモリに保管するコピー用に、「暗号化してエクスポート…」はSQLiteファイルを
  8文字以上のパスワードで暗号化して書き出します：AES-256-GCMで、鍵はPBKDF2-SHA-256（60万回の反復、
  ランダムなソルト）から導出されます。パスワードがないと、Cashflowを含め誰もファイルを開けず、
  忘れたパスワードは復元できません。インポート時にはパスワードが求められます。ブラウザ内のデータ
  はそのままで、暗証番号の保護下にあります。

## 翻訳

英語のテキストはコード内にそのまま残ります：`t('accounts', 'Reconcile')`、`tn('time', '{count} day
ago', '{count} days ago', n)`、そしてテンプレート内の `data-i18n="context"` /
`data-i18n-attr="context"` です。最初の引数はコンテキスト——その文字列が属するインターフェースの
部分——で、これにより同じ英単語を2か所で別々に翻訳できます。辞書ファイル `src/locales/<code>.json`
は「コンテキスト → 英語のテキスト → 訳語」というマッピングになっています：

```json
{
  "accounts": { "Reconcile": "Сверить" },
  "time": { "{count} days ago": { "one": "{count} день назад", "few": "{count} дня назад", "many": "{count} дней назад", "other": "{count} дня назад" } }
}
```

辞書に存在しない文字列は英語のまま表示されます。数値を含むテキストは、その言語の複数形カテゴリ
（`Intl.PluralRules`）ごとに1つの形を持ち、英語の複数形をキーとします。`npm run i18n` は言語ごとに、
まだ翻訳されていない文字列と、もう使われていない文字列を一覧表示します。`npm test` は、すべての
訳語が英語のプレースホルダーを保持し、すべての複数形を備えているかを確認します。「Cashflow」という
名前は決して翻訳されません。

このREADMEも同様に翻訳されています：言語ごとに `docs/readme/README.<code>.md` が用意され、それぞれ
の先頭に言語一覧があります。ここでの変更は、各翻訳にも反映されるべきです。

## ビルド

```sh
./build.sh            # 必要なら依存関係をインストールしてから build/cashflow.html をビルドする
npm install
npm run build         # -> build/cashflow.html と build/pages/
npm run watch         # src/ の変更を検知して再ビルドする
npm run typecheck     # tsc --noEmit
npm test              # コア部分のテスト：money、valuation、schedules、reconciliation、forecast、goals、state、SQLite、辞書
npm run test:browser  # 無頭Chromeでビルド済みのページとPWAをテストする
npm run i18n          # 各辞書に不足している、または不要になった文字列を列挙する
npm run check         # typecheck、test、build、test:browser を順に実行する
npm run shots -- shots/after  # ビルド後、すべてのタブのスクリーンショットを shots/after に保存する
node tools/icons.mjs  # assets/icon.svg からPWAのPNGアイコンを生成する
```

`build.mjs` は esbuild を使って `src/app/main.ts` を1つのIIFEにバンドルします——SQLiteのWebAssembly
はesbuildのバイナリローダーによってバイト列として組み込まれます——そしてスタイルとアイコン（data
URI）とともに `src/app/template.html` に差し込みます。その結果できるのが約1.4 MBの
`build/cashflow.html` で、その大部分はSQLiteで、続いて16の辞書が含まれます。

同じ実行で `build/pages/` も書き出されます：インストール可能なPWAとしてのそのページです——マニフェ
ストへのリンクと、ページにワーカーを登録させる `<meta name="service-worker">` を持つ `index.html`、
`manifest.webmanifest`、アイコン類、そしてページをキャッシュしてオフラインで開けるようにする
`sw.js` です。

`tests/app.mjs` はDevToolsプロトコル（依存関係のない `tools/chrome.mjs`）を介して、無頭Chromeで
ビルド済みのページを操作します：初回起動、課題の例にある口座とその合計、1週間間隔の2回の照合
（未記録 −1 500）、履歴を変えずに操作を削除すること、過去の照合、目標、エクスポート→消去→インポ
ート、PWAのオフライン動作とその更新、携帯電話での表示、そしてディスクから開いたページがデータを
保持すること。時間の経過は待ちません：ページ自身のスクリプトより前に挿入されたスクリプトが
`Date.now()` を置き換え、タイムゾーンはEurope/Kyivに設定されているため、時計の切り替えがある週も
テストされます。

## バージョンとリリース

バージョンは `package.json` の1か所だけに書かれています。ビルドはそれをページ（設定画面の下部）と
PWAのキャッシュ名に反映します。`v<version>` というタグが付いたコミットのビルドではそのまま表示され、
それ以外のコミットでは `0.1.0+1a2b3c4` のようにコミットハッシュが付加され、`main` ブランチのページ
がリリース版と誤認されないようにしています。

```sh
npm version minor           # 0.1.0 -> 0.2.0：package.json、package-lock.json を更新し、コミットとタグ v0.2.0 を作成する
git push --follow-tags      # このタグが .github/workflows/release.yml を起動する
```

タグと `package.json` の内容が一致しない場合、リリースのワークフローは停止します。一致していれば
`cashflow-<tag>.html` と `SHA256SUMS.txt` を添付します。

## GitHub Pages

`.github/workflows/pages.yml` は `main` へのすべてのプッシュでビルドとテストを行い、`build/pages/`
をGitHub Pagesにデプロイします（Settings → Pages → Source: GitHub Actions）。
<https://cash.marketkernel.com> で提供されます：ドメインは Settings → Pages → Custom domain で
設定し、Enforce HTTPSを有効にします——service workerにはHTTPSが必要です。ワークフローによる
デプロイには `CNAME` ファイルは不要です。`build/pages/` 内のすべてのパスは相対パスなので、同じ
ビルドがドメインのルートでも、プロジェクトサイトの `/<repo>/` プレフィックス配下でも動作します。

オンライン版のデータはそのアドレスに紐づいています。ディスクから開いたコピーは、それ自身のデータ
を持ちます。以前のアドレス `marketkernel.github.io/cashflow/` は現在このドメインへリダイレクト
されますが、そのデータは元の場所に残ったままです：それを使っていた人は、まずそこでデータを
エクスポートし（そこからインストールしたアプリはオフラインで動き続けます）、新しいアドレスで
インポートしてください。

デプロイのたびに `sw.js` 内のキャッシュ名が変わるため、ブラウザは新しいワーカーを自動的に取得
します——接続のある状態での起動時、アプリを開いている間の数時間おき、または設定の「更新を確認」を
押したときです。新しいワーカーは自分のバージョンを専用のキャッシュにダウンロードして待機します。
現在動作中のワーカーは、オフラインでも古いページを提供し続けます。そして設定タブにドットが付き、
「バージョン…の準備ができました」と表示されます：「更新」を押すと待機中の内容が保存され、新しい
ワーカーに切り替わってページが再読み込みされ、更新されたことが一度だけ表示されます。ボタンを押さ
なくても、アプリのすべてのウィンドウが閉じられれば新しいバージョンが自動的に有効になります。
ダウンロードしたファイルはそのバージョンのまま変わりません。ディスク上のバージョンを特定したい
場合は、リリースから `cashflow-<tag>.html` を取得し、`SHA256SUMS.txt` と照合してください。

## 制限事項

- 端末間の同期はありません：データは入力したブラウザの中にとどまります。移動するには、一方で
  エクスポートし、もう一方でインポートします。
- 為替レートは手入力です：アプリはレート取得のためにオンラインに接続することはありません。
- ディスクから開いたページは、そのブラウザのローカルファイル用ストレージにデータを保持します。
  ChromeとEdgeは保持します（ブラウザテストで確認済み）。FirefoxとSafariも通常は保持しますが、一部
  の設定やプライベートウィンドウでは保持されません——その場合ページの上部にその旨が表示され、
  メモリ上でのみ動作します：データをエクスポートするか、インストール済みのアプリを使ってください。
- ローンの利息はモデル化されていません。定期的な支出として自分で追加してください。
- 目標は順番どおりに、ひとつずつ購入されます。リストの下にある安い目標は、今すぐ買えるとしても、
  上にある目標を待ちます。
